# Licensing and Reuse

## Current State

No repository-wide license has been selected. Until an explicit license is added, do not assume that public visibility grants permission to reuse or redistribute all code and data.

The repository combines original code, generated bibliographic metadata, outbound links, and an archive whose contents and rights have not been fully reviewed. Applying a permissive license to the root without checking those materials could imply rights the maintainer does not hold.

## Recommended Separation

1. **Original source code:** choose an explicit software license after confirming authorship and contribution history.
2. **Documentation:** determine whether it should use a documentation-oriented license distinct from the code license.
3. **Curated source registry:** generally consists of factual link metadata and original descriptions, but still requires appropriate attribution and a reviewable provenance policy.
4. **Provider-derived metadata:** check source terms, attribution requirements, licensing, caching, and redistribution rules for each provider.
5. **Abstracts, excerpts, and full text:** do not assume these can be republished merely because an API returns them.
6. **Generated index files:** publish a clear statement about the source data, derivation, attribution, update date, and applicable restrictions.
7. **Binary archives:** inspect contents, provenance, and rights before deciding whether the archive should remain distributed with the source repository.

## Release Requirement

Before a public release is presented as a reusable open-source package or dataset, select and document the relevant code and data terms. Do not use a code license to override source-provider restrictions.
